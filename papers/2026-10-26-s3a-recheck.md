## Remaining consequential defects

### R1 — High: chapter table can allocate after the cut has been recorded

**Source:** `src/context.cpp:2666–2695`, specifically `log_.record` at 2679 followed by `chapter_.table.push_back` at 2690; `reserve_append` exists at 338–347 but is called only for `captured_` here. The B4 change removed the old pre-record owned-table preparation without reserving the destination table before publication.

**Exact input/failure point:** a fresh store with an appended user prompt; issue an identity, compose start using current head and empty chapter, and write via `cut(frame, identity)`. Fail allocation of the first `chapter_.table` buffer at line 2690, after `log_.record` has succeeded. Likewise any later cut at a chapter vector capacity boundary.

**Actual source-derived outcome:** the cut record is durable, but the call throws before installing the new chapter and head (and, for non-start cuts, before swapping the new entries). New originals/classes may already have been merged. Live store state no longer equals replay. A later write from the unchanged head can make a journal suffix whose observed/base does not follow the recorded cut. The failure is not an ordinary pre-record refusal.

**Expected:** reserve the one-row table growth before the record, then publish the owned row/binding without allocation. On reserve failure, no cut is recorded and visible state remains unchanged. Do not restore the quadratic copy. Playback has the corresponding late push after entry/class publication at 907–910; its allocation failure should not leave partially installed state if that path remains recoverable.

**Missing direct oracle:** inject failure at chapter growth on first start and at a later growth boundary; assert no recorded cut on pre-publication allocation refusal, unchanged live state, and live/reopen/whole-history agreement. This specifically targets the B4 remediation, not a request for general allocator testing.

### R2 — Medium: restore plus explicit replacement preserves a false archive row

**Source:** `src/context_cut.cpp:1405–1407` skips note rewrite whenever `replaced.contains(note)`. Sweep similarly excludes replacements (1390–1393). The test reference explicitly repeats this exception at `tests/cut_compose_test.cpp:642–645`.

**Exact input:** on the OpenAI keep profile, archive a normal completed round U, obtaining live archive note N whose sole row lists U. In one `CutRequest`, restore U from its original items/classes and replace entry N with its identical existing item (or an otherwise valid content edit preserving U's row). Default protection stays enabled; N is an unpinned `UnitClass::note`, not an instruction.

**Actual source-derived outcome:** replace is accepted; restore discovers N; N is neither absorbed nor rewritten/swept because it is explicitly replaced; U's originals are inserted after N. N still states that U left the live context and advertises U as archived. This violates §5.5's invariant that the note never claims a restored unit is still gone. No malformed item or forged handle is necessary.

**Expected:** either refuse the conflicting combined request before recording, or reconcile the replacement with removal of restored rows (sweep the empty note). The model edit cannot silently override the harness's archive-row invariant.

**Missing direct oracle:** assert for a combined restore + note replace that every restored handle disappears from all live archive-note rows. Do not derive this expectation from the current “edit wins” exception.

### R3 — Medium: replacing the newest boundary bypasses its protection

**Source:** newest-boundary detection at `src/context_cut.cpp:1252–1257`; protection exists only in `take` (1293–1295), not in replace validation (1321–1351). `protected_unit` (`src/context_units.cpp:534–537`) protects instructions, tool state and pinned units, not ordinary notes.

**Exact input:** OpenAI profile with enabled `user_note`, context containing an operator prompt, a completed tool round, and a composer-created newest boundary N at the tail. Submit a sole replace edit for N, preserving its `type: message`, changing role to `developer` and content to ordinary input text without the boundary marker. No call ID/native fields are involved; N is unpinned.

**Actual source-derived outcome:** replacement passes, exports, and removes the newest boundary's user turn-start semantics. The tail becomes open under `user_text`; the newest boundary that is declared “never selectable” has been edited away. `take` would have refused removal/move/summary of the same unit. The reference has the same replace-path omission, so model agreement is not an independent defense.

**Expected:** newest boundary replacement is refused as `protected`, just like selection through `take`, regardless of its valid replacement type. Add a direct replace case; a remove-only protection test does not cover this path.

## Consequential direct-oracle gaps beyond the defects

1. **Stale head and chapter conflict (B2/B3):** persistence currently sets the head immediately before every compose/write. It never composes, appends, then attempts the old identity-bound frame. Add that exact append-cut race and a wrong-previous/ordinal write; assert `conflict`, no accepted cut publication, unchanged current entries/chapter, and equality on reopen. Existing `advance_chapter` corruption checks do not exercise writer error translation.
2. **Removed-anchor/boundary regressions (A-H1/M1):** mixed generation and reasoning-ending units now reach these fault classes, and the boundary reference is stronger. Still missing named deterministic direct cases for archive + insert/move after a reasoning-only unit; restore + insert after its emptied note; and no-note tail restore + boundary. Assert apply succeeds, all requested non-reasoning inserts survive, and the boundary is physically last and a wire turn start. Existing `turn_states` tests an archive boundary, not the tail-restore combination.
3. **OAuth prefix binding (B5):** directly compare `anthropic_system_text(instructions, false/true)` with export's `system`, hash those exact texts, and compose the resulting prefix-checked rebind; expect changed digest, p=0 and all post-prefix reasoning dropped. The new helper/contract is reasonable with no callers, but current fixture binding hashes literal `"be careful"` (test 969), not codec-exported text.
4. **Ordinal zero (B6):** use a valid encoded binding and mutate only ordinal. This makes the existing check sensitive to the claimed fault.

The downgrade fence itself is correctly ordered in source, and the test asserts level 2 for a no-key start. This recheck did not run an older binary or repeat the prior differential codec experiment. The readback oracle genuinely reaches the current handler; its present small fixtures do not establish large-entry pagination behavior, which is not elevated to a new S3a defect here.
