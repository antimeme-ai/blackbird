## 2. Deep-Dive Comparison Across the Four Technical Axes

### 2.1 Identity & Sovereignty (Per-Human Keys vs Shared Session)

Three distinct identity architectures emerge across the corpus:

1. **Sovereign per-actor cryptographic keys (AgentLink, Ligus, Block Buzz, Blackbird).**
   - **AgentLink** binds persistent Ed25519 keys to a room secret via first-contact HMAC proofs and pins the peer's public key in per-room trust files (`<config>.<roomId>.trust.json`), refusing silent key swaps even if the relay loses state (`agentlink/docs/PROTOCOL.md`).
   - **Ligus** separates account-level Ed25519 signing keys (16-byte safety code) from per-device keys (10-byte formatted fingerprint like `7F3A-91C0-77DE-0B14-5E62`, spoken `aria-label`, explicit verification checkbox) and seals payloads per-device via X25519/HPKE (`ligus/docs/design/devices-and-keys.md`).
   - **Block Buzz** unifies human and agent identity under Nostr Schnorr keypairs (`NIP-42` challenge/response and `NIP-98` HTTP auth): the relay rejects any event whose `event.pubkey != auth_context.pubkey`, making human and agent provenance cryptographically indistinguishable in shape (`block-buzz/ARCHITECTURE.md` §4, §6).
2. **Ephemeral/shared-secret pairing with TOFU or room tokens (Magpie, session-multiplayer, Coopagents).**
   - **Magpie** optimizes for zero-setup onboarding: a single-use `~59-bit` pairing code (`K7F3-9M2P-XQ4R@wss://...`) derives both the relay's opaque `rendezvousId` and the endpoints' `AES-256-GCM` channel key via `HKDF-SHA256`, with optional Ed25519 `identity/1` exchange inside the encrypted tunnel (`magpie/docs/PROTOCOL.md`).
   - **session-multiplayer** uses a permanent 32-byte shared room key (Argon2id-sealed during pairing) plus Ed25519 TOFU signatures—explicitly acknowledging that losing/leaking a room key permits no eviction and provides no forward secrecy (`session-multiplayer/PROTOCOL.md` §9).
   - **Coopagents** uses Iroh's persistent Ed25519 endpoint ID for QUIC transport reachability, layered underneath per-member opaque bearer tokens stored as SHA-256 hashes in the host's SQLite DB (`coopagents/src/p2p.py`, `src/identity.py`).
3. **Centralized org/token identity (HumanLayer, Hivemind, A2A).**
   - **HumanLayer** and **Hivemind** treat identity as org accounts / bearer tokens (`WorkOS` + daemon tokens in HumanLayer; single `WT_TOKEN` + self-asserted `actorId` in Hivemind). **A2A** delegates identity entirely to HTTP enterprise auth (`OAuth2`/mTLS) plus optional signed `AgentCard` manifests.

**Gap relevant to Blackbird:** None of the peer-to-peer systems combine **self-certifying per-human Ed25519 keys** with **delegated sub-actor / scoped capability attribution** (`owner_actor` vs `requested_by_actor` vs `grant_id`). Buzz's relay knows *which* key signed an event, but treats an agent key as a peer principal with `Scope::all_known()` after NIP-42 rather than a bounded delegate of a specific human owner.

### 2.2 Authority, OPCON, Revocation & Kill-Switch

- **Provider ToS boundary (Magpie `docs/COMPLIANCE.md`).** Magpie codifies the sharpest product/legal invariant in the entire corpus: *each agent runs strictly on its owner's own credentials/CLI*. Mode 3 ("human A directly steering human B's subscription seat") is explicitly prohibited as credential sharing under Anthropic Consumer Terms and OpenAI Services Agreement. AgentLink adopts the identical stance: persistent listening is availability, not standing execution authority; local read-only policy and approval gates remain with the owner.
- **Prompt-injection containment (Magpie, AgentLink, Coopagents, ACP).**
  - **Magpie** (`packages/protocol/src/security.ts`) wraps inbound peer text in `<<<UNTRUSTED PEER MESSAGE — BEGIN/END>>>` markers and **rewrites any occurrence of the marker prefix inside peer text** (`<<<(marker text written by the peer)...`) so a malicious peer cannot break out of the quote fence.
  - **Coopagents** (`src/space_wake.py`) enforces two clean rules on automated wake notices: (a) wake text contains **counts only** (never teammate body text), and (b) unattended responses may read files/team state but **must not run shell commands** while the human may be away.
  - **ACP v2** (`docs/protocol/v2/security.mdx`) adds terminal/UI hygiene often overlooked by protocols: strip/reveal Unicode bidi/zero-width/tag characters in paths/commands/diffs and neutralize terminal escape sequences before printing agent text.
- **Revocation, approval gates, and kill-switches.**
  - **AgentLink** implements a clean local `manual` approval gate (`held` state): held requests are hidden from MCP `inbox_list`/`inbox_claim`, exposed only to the owner's desktop UI, and local denial reasons never leak to the remote peer (`agentlink/docs/PROTOCOL.md`).
  - **Hivemind** introduces **monotonic fence tokens** on symbol/file claims (`packages/coordination-mcp-server/src/server.ts`) so a stalled or revoked holder cannot clobber a newer lease—and differentiates policy by party (`agent`-vs-`agent` hard-blocks; `human`-involved soft-warns).
  - **Ligus** implements cryptographic `DeviceRevoked` events + workspace key rotation, plus an **"install-is-inert-until-enabled"** gate for MCP tools (`ligus/SECURITY.md`).
  - **HumanLayer** provides centralized remote approval resolution (`approvals/resolve.ts`), while **Buzz** provides relay-side member removal (`buzz-admin remove-member`, `kind:13534`)—neither gives an offline/partitioned owner a local tool-time capability kill-switch.

### 2.3 Wire Protocol, Partition Ordering & Receipt vs. Inclusion Semantics

A major architectural divide splits the corpus into **centralized total-order logs** vs **partition-tolerant peer messaging**:

- **Centralized total order (Buzz, HumanLayer, Hivemind, Coopagents host-SQLite).**
  - **Buzz** writes every Nostr event to one Postgres `events` table (`ON CONFLICT DO NOTHING`) and returns `["OK", id, true]` only after DB commit + FTS indexing + fan-out. Simple, searchable, zero conflict resolution—but the relay is a single point of truth and availability; offline partitions cannot commit.
  - **HumanLayer** syncs Postgres via ElectricSQL shapes; **Coopagents** hosts one authoritative SQLite DB per room on the owner's machine and tunnels HTTP/MCP/WS to peers over Iroh QUIC (`coopagents/src/p2p.py`).
- **E2EE blind relays & P2P gossip (AgentLink, Magpie, Ligus, session-multiplayer).**
  - **Ligus** explicitly avoids a full CRDT by designing `SessionEvent` variants to be commutative/idempotent under replay (`ligus/docs/architecture.md` §3), while still tagging events with `(session_id, sequence)`.
  - **session-multiplayer** heals partial P2P meshes via store-and-forward gossip (`id`-deduplicated 200-msg room logs + unacked outbox replay on reconnect), with no causal parent references—concurrent conflicting intents simply interleave by wall-clock `ts`.
- **Receipt vs. cognitive inclusion semantics (critical for *Worse Together* N1).**
  - Almost every system stops at **transport or application-inbox receipts**:
    - **session-multiplayer:** single `{"t":"ack","id":...}` on socket receipt.
    - **Buzz:** relay `["OK", id, true]` (relay accepted), nothing per-recipient.
    - **AgentLink** gets closest on delivery mechanics: `queued_local -> relay_acked -> queued -> claimed (lease) -> processing -> responded/declined/expired`, explicitly warning that `relay_acked` proves only ciphertext arrival, not peer decryption or handling (`agentlink/docs/PROTOCOL.md`).
    - **Coopagents** (`src/messages.py`) explicitly separates `delivery_id`, `read_at`, `processed_at`, and resolution—and ensures the host board's read-only `snapshot()` **never triggers receipt-writing `read_inbox()`** (`src/space_board.py`: *"Common snapshot uses list_requests, never the receipt-writing read_inbox"*).
    - **ACP v2** (`prompt-lifecycle.mdx`) defines `session/prompt` response as proving insertion into the agent's conversation (`messageId`), distinct from completion.
  - **None of the ten references** bind a receipt to a cryptographic `request_hash` proving inclusion in a specific LLM inference request, nor do any implement an **action-time unread-message guard** scoped to a contested resource before executing an irreversible tool call. Blackbird's Stage 0 `BoardBridge` (`ReceiptStage::included_in_request` + `check_action_guard`) is ahead of the entire field here.

### 2.4 Context Isolation vs. Sharing & Harness Neutrality (MCP / ACP / A2A)

- **Three distinct protocol boundaries are crystallizing—and should NOT be conflated:**
  1. **MCP (tool/board surface into existing harnesses):** Used by AgentLink, Magpie, session-multiplayer, Hivemind, and Coopagents to plug Claude Code, Codex, and other clients into a shared room without migrating harnesses. *Limitation:* Standard MCP is pull-based and cannot reliably inject a new model turn into an idle GUI/CLI session (documented independently by AgentLink, session-multiplayer, and Coopagents—all three resort to harness-specific stop/PreToolUse hooks or experimental background watchers).
  2. **ACP (editor/orchestrator driving a local coding agent subprocess):** Used by **Block Buzz** (`buzz-acp` pooling 1–32 Goose/Codex/Claude processes over stdio JSON-RPC with per-channel serial queuing) and **Ligus**. Clean way to drive external harnesses programmatically without scraping PTYs or touching provider OAuth.
  3. **A2A (opaque enterprise agent-to-agent task exchange):** Clean async task/artifact/cancellation envelope (`a2a.proto`) for crossing organizational boundaries where internal context/tools are intentionally hidden, but heavy for tight two-developer coding loops and lacks peer-owned E2EE or local capability grants.
- **Context boundary consensus:** Every peer-sovereign system (AgentLink, Magpie, Coopagents, A2A) keeps private repos, credentials, and full transcripts **local** and moves only scoped artifacts, questions, structured resolutions (`agreed[]`/`contested[]`), or versioned interface contracts across the wire. By contrast, Hivemind's live Yjs working-tree mirror explicitly warns that *"convergence is not correctness"*—two agents rewriting the same function silently corrupt code unless guarded by pre-edit region claims.

## 3. Concrete Takeaways & Design Pitfalls for Blackbird (Stage 0 -> Stage 2)

Blackbird's Stage 0 (`PeerIdentityStore`, `KnownPeersStore`, `BoardBridge` with `CausalEvent`, 6-stage `MessageReceipt`, `ActionGuardVerdict`, `format_quoted_peer_frame`, `SpendLedger`, `authorize_tool_call`, and `PresenceRecord`) already avoids the worst traps in this corpus. The acquired references yield specific, actionable upgrades and pitfalls across our roadmap:

### Stage 0 -> Stage 1 (Two-Owner Cross-Machine Proof & Swarmboard/TUI UX)

1. **Harden quote-framing against delimiter breakout (from Magpie `security.ts`).**
   Verify that `format_quoted_peer_frame()` escapes/rewrites any peer-authored occurrence of its own begin/end fence markers, and combine with ACP v2's terminal hygiene (neutralize ANSI/CSI control sequences and reveal/strip Unicode bidi/zero-width characters before rendering peer strings in Blackbird's TUI Swarmboard).
2. **Never let passive TUI/board snapshots mutate receipt state (from Coopagents `space_board.py`).**
   Opening or refreshing a Swarmboard pane for human inspection must read messages *without* advancing an agent's `opened_by_application` or `included_in_request` receipt—otherwise human glancing at the TUI silently disarms `BoardBridge::check_action_guard()`.
3. **Adopt Magpie's structured `resolution/1` (`agreed[]` / `contested[]`) and Coopagents' versioned contracts for Swarmboard views.**
   Free-form chat transcripts scale poorly for multi-owner review (Grok recon + Magpie). Rendering `ConcurrentClaimConflict`, `agreed`/`contested` points, and explicit `held` approval cards (with local-only denial reasons, per AgentLink) makes cross-owner state legible in the TUI without flooding the conversation pane.
4. **Keep wake notifications body-free and read-only by default (from Coopagents `space_wake.py` & AgentLink `wakeMode`).**
   When waking an idle Blackbird or external MCP peer, emit only counts/event-hashes (never untrusted peer text in the wake prompt) and never assume standard MCP can push-wake an unarmed GUI; keep durable inbox + explicit claim leases with crash-recovery requeue on broker restart.
5. **Enforce Magpie's compliance boundary in OPCON modes.**
   Keep Stage 1 peer work-order mode (`CapabilityGrant` executed by the owner's own local harness under owner's local `authorize_tool_call` + `SpendLedger`) strictly separate from any direct foreign-seat steering, and never touch, proxy, or forward provider credentials.

### Stage 1 -> Stage 2 (NAT Traversal, Blind Relay & Many-Party Groups)

6. **Separate reachability/relay from room cryptography and causal history (from AgentLink, Magpie, Ligus, Coopagents).**
   - A Stage 2 blind relay should only see opaque `rendezvousId` / `room_id`, rate-limit/quota headers, and AEAD ciphertext—never room secrets or plaintext.
   - Bind peer Ed25519 keys at first contact using out-of-band pairing codes (ideally PAKE/SPAKE2 as Magpie plans, or Ligus-style spoken/grouped fingerprints) so a compromised relay cannot MitM initial key exchange.
   - Retain Stage 0's per-actor `(actor_id, actor_seq, causal_parents, event_hash)` DAG when adding a blind relay; **do not** regress to a relay-assigned global sequence number (Buzz/HumanLayer) or wall-clock-only ordering (session-multiplayer), which break offline partition reconciliation.
7. **Pitfall: Permanent shared room keys cannot support member revocation (from session-multiplayer §9).**
   Do not reuse a static 256-bit room key for >2 participants; follow Ligus's per-device sealing / key-rotation path or evaluate RFC 9420 MLS for Stage 2 groups, while keeping local tool-time revocation (`KnownPeersStore::revoke_grant` + Hivemind-style monotonic fence tokens on shared worktree/resource claims) authoritative even during network partitions.
8. **Use ACP (not custom PTY scraping) for local external-harness workers, and keep A2A as an optional outer bridge.**
   Block Buzz's `buzz-acp` demonstrates that driving Goose/Codex/Claude via ACP with per-channel serialization cleanly decouples harness churn from the room substrate, while Blackbird's existing MCP surface remains the zero-migration entry point for already-running external harnesses.
