# Retained image inputs and application provider selection

Application-open forwards an explicit provider and emits the actual provider in
ready. Oxcart verifies this echo before accepting a routed connection. read_image
preserves complete original file bytes and returns an immutable journal reference.
Default turn.lua explicitly emits image tool-result parts. CodingEngine loads
those originals into transient API input_image parts only immediately before
provider.respond; native context/checkpoints keep the compact reference. Path
mutation/deletion cannot alter retained replay.

Responses already supports explicit image output parts. The Anthropic adapter
translates them to Messages image blocks. Request JSON encoding and auth HTTP
transport no longer impose the unrelated16MiB text-body ceiling on whole images;
raw audit capacity reserves the actual encoded body before the HTTP effect.
MIME recognition covers PNG/JPEG/GIF/WebP; image interpretation remains a provider
operation, not an inference from a filename or a hex/text fallback.

The local HTTPS application fixture uses a dummy private test key, full Oxcart30
tool catalog and actual Responses SSE/function loop. It sees exact original PNG
bytes despite a changed path, executes a native query, then reopens the retained
session after deleting the input path and sees the same pixels. Old provider-auth
and Anthropic image-result sources fail direct17MiB/image oracles; current focused
image/auth/provider/application/coding checks pass. No real key, browser launch or
inference is used. Failed fixtures and compiler/analyzer results remain outside
Git in the Oxcart mission records. One whole-unit review and root-owned native/model
acceptance follow. Existing macOS-qualified tooling is not claimed as a Linux
full-gate pass; unchanged Child/CodingEngine padding warnings remain explicit.

The actual large valid-PNG HTTPS oracle additionally exposed curl's config-line
limit. CurlBody now passes complete large bodies through an unlinked private
CLOEXEC file mapped only into the owned curl as fd3. Credentials stay in stdin
config; original API bytes are retained before staging. Both ordinary auth and
legacy OpenAI use this path; small request behavior is unchanged. The initial
failed candidate remains alongside its successor. Source: curl's official manual
https://curl.se/docs/manpage.html, config and data-binary sections.

The sole whole-unit review is complete. Its one finding concerned Oxcart's

intent. Root found no other issue and directed matched staging. The packaged
complete-body successor passes actual local HTTPS requests exceeding17MB,
