# Native Send, held next turns and captured main stop

This document describes the T1 source candidate, not runtime installation or
whole-contract qualification. Its direct results and remaining gaps live in the
commissioned run, `context/autodev-2026-10-26/chat-t1-02/STATUS.md` (ignored evidence).

## Owners and boundaries

`Composer` requests a native intention identity at deliberate Send, before
clearing its draft. Production identity comes from the actual raw acquisition
reference; capture-disabled embeddings explicitly use process-local identities.
Two equal intentional sends are different intentions. `NextTurns` owns immutable
shared text revisions and submitted local route, keyed edit buffers, acceptance
order and launch permission. `observed_route` is separate from the immutable
submitted route: Send targets native terminal dispatch, not a guessed provider.
The same native owner is accessible through the `next_turns` structured tool and
Lua `blackbird.call("next_turns", ...)`. These are not live-steering a main turn.

The terminal receipt is keyed by intention. Launch updates it, without another
YOU block. An acquired/queued receipt is not context inclusion or provider
receipt. CodingEngine publishes its actual appended context identity and, at
local attempt commitment, membership of that identity in the assembled context.
No stable relation means unavailable; equal text is never a join. A `/lua`
execution is local program routing, not provider delivery. Attempt commitment,
local interruption and remote disposition are distinct; remote remains unknown
in the safe provider fixtures.

## Correction and recovery

Ctrl-R or `/queue` opens the keyed Next turns shelf. `/next edit ID REV` holds
that exact pending revision before loading its private buffer. The unrelated
composer and cursor are parked first. Enter applies the private buffer as a new
immutable revision **and keeps held**. Ctrl-G returns to the parked composer but
keeps the dirty buffer. Dirty release refuses. `/next release ID REV` releases
only the selected clean revision; `/next hold`, `/next discard` and `/next
withdraw` also require exact ID and revision. Runnable items retain acquisition
order; holding one does not authorize another. Model/Lua operations use the same
mutex and revision checks. Structured buffer/apply/discard additionally require the
independently returned `edit_version`, so a stale private buffer cannot overwrite
a newer one. Stale native editing preserves the proposal as an independent draft
with its predecessor and restores the unrelated composer. A launch winner is no
longer editable.

The owner retains up to256 receipts and a conservative1MiB owned payload/metadata
envelope. Full admission refuses before clearing the composer, rather than
silently evicting history. Shared immutable revision payloads are also held by
the worker; snapshots don't clone text history. Binary UI-state projection does
materialize bytes for the existing native save protocol. The existing audit/raw
capture, save/durability and refused/unknown custody fences remain authoritative.
No JSON representation is used inside the owner or saved UI state.

Checkpoint generation and acknowledgment fence launch against a correction
between snapshot/save and dispatch. Save refusal holds work. A failed worker
construction is known not started and leaves its item held. On reopen unresolved
items are recovered, never runnable. Dirty recovery bytes stay owned; `/draft N`
loads recovery and a new explicit Send has a predecessor reference. Reopen is
not automatic replay, and persistence of intent is not proof an operation ran.
Independent/unkeyed picker drafts and their predecessors are separately owned in
the binary state; withdrawn text is available through `/drafts`. `/receipts`
inspects historical keyed relations; `/queue` shows current owner revisions, not
the historical transcript text. Explicit CLI objectives/restart continuation are
new authorized items; they do not release or replay the recovered shelf.

## Stop and Back

Decoded Escape has main-stop priority while active, including palette and
inspector routes. Ctrl-C is the fallback; Ctrl-G is local Back. Escape is decoded
using the existing legacy prefix/deadline policy, not raw-byte-arrival ordering.
Literal pasted controls stay data. Private foreground PTYs still own literal
Escape,03 and18 for their exact foreground epoch; Ctrl-B returns to the harness,
then a harness stop can target the captured main turn. External editors own keys
and remain idle-only (`Alt-E` or `/edit`). Startup questions still require their
owned answer, not a guessed objective.

The UI thread captures its actual current token, holds pending work, and closes
that generation's dispatch permission before any later launch. Repetition is
idempotent for the captured token, and cannot retarget a replacement turn.
`TurnDispatch` serializes native stop against provider attempt commitment,
including retry commitment after a timer. Stop winning means no new commitment;
dispatch winning means an attempt can exist, with cancellation/remote unknown
reported separately. Local success is not relabeled interruption just because a
stop was requested. The result label follows the actual local return/error.
Stop is never undo. A new deliberate Send authorizes only its new item, not the
held shelf; release authorizes only the selected item.

The present terminal dispatch fence covers existing queued engine command,
workflow and settings routes as well as objectives. Future T5 native definition
operations must use this same admission boundary. No T5 definition transaction
API or editor UI exists in this candidate.

Native control service does not await Lua composition or output drain. Existing
partial-write packet/baseline machinery remains in place. Current mouse support
is scrolling/navigation, not new click-to-release/stop/withdraw buttons. T1 does
not introduce pointer effects or reinterpret uncertain partial/resize geometry
as a new target. Any future effectful pointer route must capture exact target and
revision from a coherently completed emitted frame and refuse uncertain geometry.
Reading-layout redesign remains outside T1.

## Direct evidence is not whole qualification

The actual-main old three regressions have retained RED and GREEN originals.
Correction/release uses independently returned IDs and an independent filesystem
effect. Isolated fake registered-provider fixtures cover response wait, retry
wait, partial stream, and output pressure: native saved result before drain and
coherent eventual screen are separate observations. Native raw write returns
provide the actual EAGAIN evidence; transport request ledgers and partial bytes
remain intact. These do not qualify remote stop, live accounts, physical display,
accessibility or expert usability. Full source/host/screen/performance gates and
the bounded independent source review/recheck have their own recorded outcomes.
